
# Часть 1 Теория

## 1 Структура запроса и ответа

**HTTP-запрос** состоит из следующих основных частей:
* *Стартовая строка (Request Line)*. Она включает в себя *метод (например, `GET`, `POST`), *путь к ресурсу* (`/` или `/api/login`) и *версию протокола (`HTTP/1.1`).
* *Заголовки.* Это набор пар `ключ: значение`, которые передают служебную информацию о запросе и клиенте. Например, `Host: example.com` указывает, на каком сервере искать ресурс. Раздел заголовков заканчивается пустой строкой.
* *Тело запроса.* Содержит данные, которые клиент передает на сервер (например, заполненную форму).

**HTTP-ответ** состоит из следующих основных частей:
* *Стартовая строка.* Содержит *версию протокола* (`HTTP/1.1`), *код состояния* и краткое *пояснение* к коду (`OK`, `Not Found`).
* *Заголовки.* Набор пар `ключ: значение`, предоставляющий клиенту мета-информацию об ответе и сервере: `Content-Type` сообщает формат передаваемых данных, `Content-Length` - их размер.
* *Тело ответа. Необязательная часть. Содержит непосредственно запрошенные клиентом данные.
## 2 Коды состояния

HTTP-статус коды делятся на 5 классов:

1. **1xx (Информационные)**
    Пример: `100 Continue` - сервер получил заголовки запроса и предлагает клиенту продолжить отправку тела.
2. **2xx (Успех)** 
    Пример: `200 OK` - Запрос выполнен успешно, и результат (если он есть) находится в теле ответа.
3. **3xx (Перенаправление)**
    Пример: `301 Moved Permanently` - Запрошенный ресурс был окончательно перемещен по новому URL, который указывается в заголовке `Location`.
4. **4xx (Ошибка клиента)**
    Пример: `404 Not Found` - Сервер не может найти запрошенный ресурс по указанному пути.
5. **5xx (Ошибка сервера)**
    Пример: `500 Internal Server Error` - На сервере произошла непредвиденная ошибка, которая помешала ему обработать запрос.

## 3 Методы HTTP

Основная разница между методами GET и POST заключается в их назначении и том, как они передают данные:
* **GET** предназначен для получения данных с сервера. Параметры запроса передаются в самой строке URL (после знака `?`), что делает их видимыми и ограничивает длину. GET-запросы не должны изменять состояние сервера (они идемпотентны), то есть многократное выполнение одного и того же GET-запроса не должно приводить к разным результатам. Их следует использовать для запроса страниц, картинок, результатов поиска и т.п.
* **POST** предназначен для отправки данных на сервер, что обычно приводит к изменению его состояния (например, созданию новой записи). Данные передаются в *теле запроса*. Их следует использовать для отправки форм, загрузки файлов, авторизации.

## 4 Заголовки

**Заголовки (Headers)** нужны для передачи служебной информации между клиентом и сервером.

* **Заголовки запроса (Request Headers)** отправляются клиентом на сервер. Они содержат информацию о самом клиенте и его предпочтениях.
    Пример 1: `User-Agent: Mozilla/5.0` - сообщает серверу, какой браузер или программа используются.
    Пример 2: `Accept-Language: ru-RU,ru` - указывает предпочтительный язык ответа.
* **Заголовки ответа (Response Headers)** отправляются сервером клиенту. Они содержат информацию о сервере и самом ответе.
    Пример 1: `Content-Type: text/html; charset=UTF-8` - сообщает клиенту, что в теле ответа находится HTML-документ в кодировке UTF-8.
    Пример 2: `Server: nginx/1.18.0` - указывает программное обеспечение сервера (эту информацию часто скрывают в целях безопасности).

# Часть 2 Практика

## 5 Анализ запроса

1. Метод `POST` (указан в стартовой строке).
2. Запрашивается путь `/api/login` (указан в стартовой строке после метода).
3. На сервер передаются данные формы: `username=johndoe&password=12345`. Они находятся в теле запроса (Request Body) — самой последней части, после пустой строки, отделяющей заголовки.
4. Заголовок `Content-Length: 29` сообщает серверу, что тело запроса имеет длину 29 байт. Это нужно, чтобы сервер знал, сколько данных ему нужно прочитать и когда заканчивается тело запроса.

## 6 Анализ ответа

1. Нет, запрос не был успешен. На это указывает код состояния `404`.
2. Сервер вернул данные в формате HTML.
3. Браузер должен обработать код состояния `404` и отобразить полученное тело ответа пользователю.
